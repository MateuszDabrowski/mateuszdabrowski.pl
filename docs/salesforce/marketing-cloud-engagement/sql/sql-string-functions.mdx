Salesforce :product[Marketing Cloud Engagement] SQL implementation does not support user-defined functions. There are, however, multiple built-in functions that are useful on a day-to-day basis when working with queries.

Here, I will cover only selected string functions that I find most useful for Marketing Automation purposes. They will help you change the values, split and concatenate them, or find elements within.

:::note You Should Know

All string functions in SQL use a 1-based index instead of 0-based indexing known from, for example, JavaScript. The first character starts at index 1. It is crucial to provide the correct value to the arguments and correctly interpret the results.

:::

## LEFT & RIGHT

`LEFT` and `RIGHT` functions allow you to cut down the string to just part of it.

Both require source value and the number of characters to return.

```sql title="LEFT and RIGHT can work both on strings as well as on other data types"
SELECT
      LEFT(FirstName, 1)    AS FirstNameInitialLetter
    , RIGHT(FirstName, 1)   AS FirstNameEndingLetter
    , LEFT(s.DateJoined, 3) AS MonthJoined
```

Both those functions can be beneficial to clean and streamline your data by themselves, but their real power becomes evident when you mix them with [`CHARINDEX`](#charindex) for content-aware cuts.

## LEN

`LEN` function returns a count of characters in the value.

```sql {3} title="If you use Salesforce Contact ID as Subscriber Key, use LEN to find invalid records quickly"
SELECT SubscriberKey
FROM _Subscribers
WHERE LEN(SubscriberKey) != 18
```

It is less useful for segmentation but awesome for various administrative purposes. Apart from the example above, I highly recommend checking how this function combines with [`MAX` function](/docs/salesforce/marketing-cloud-engagement/sql/sql-numeric-functions.mdx#min-and-max).

## CHARINDEX

`CHARINDEX` function lets you find if and where one string is in another. You pass the value you want to find, the value in which you wish to search and, optionally, the index from which you want to start the search.

```sql title="Search for 'Manager' in the JobTitle column starting with the first index"
CHARINDEX('Manager', JobTitle, 1)
```

I used the optional starting index in the example above, but you will not be using it in most cases. The `CHARINDEX` defaults to starting from the beginning so that we can write the above line shorter as `CHARINDEX('Manager', JobTitle)`.

The function returns one of the three possible values:

1. NULL - if either value to find or searched value is NULL
2. 0 - if the value to find is not within the searched value
3. any other digit - the index where the value to find starts within the searched value - if there are multiple occurrences, the result will show the starting index of just the first one.

By default, `CHARINDEX` in :product[MCE] is case-insensitive in its searches. You can, however, enforce case sensitivity by adding `COLLATE`:

```sql title="Case sensitive CHARINDEX search - note lack of a comma between the value and COLLATE"
CHARINDEX('Manager', JobTitle COLLATE Latin1_General_CS_AS)
```

:::note You Should Know

`CHARINDEX` is especially useful when combined with [`CASE`](/docs/salesforce/marketing-cloud-engagement/sql/sql-case.mdx#conditional-values-with-case) and [`LEFT`](#left--right)/[`RIGHT`](#left--right) functions, as it allows for smart string operations:

```sql {3} title="Dynamically pull part of the Institution Name value"
SELECT
      CASE
        WHEN CHARINDEX(' ', InstitutionName) > 0 THEN LEFT(InstitutionName, CHARINDEX(' ', InstitutionName) - 1)
        ELSE InstitutionName
      END AS InstitutionType
FROM Accounts
```

The above query checks whether there is a space within the `InstitutionName` value and if yes - it captures only the first word. Think about all the educational institution names with `University of...`, `School of...` - by taking only the first part, we can create a new simplified data point categorising records by type.

If the value you want to cut is JSON, skip the string functions and read it with [JSON functions](/docs/salesforce/marketing-cloud-engagement/sql/sql-json-functions.mdx). They handle nesting and escaped quotes for you.

:::

## PATINDEX

While [`CHARINDEX`](#charindex) is great for searching the position of a specific string in a value, `PATINDEX` gives you even more power by supporting the wildcard patterns used with [`LIKE`](/docs/salesforce/marketing-cloud-engagement/sql/sql-like.mdx) operator:

Wildcards & Operators | Description
-- | --
`%` | Zero, one or more characters
`_` | Exactly one character
`[]` | Any single character from the list specified inside
`-` | Range operator for `[]`
`^` | Exclusion operator for `[]`

To learn more about specific wildcards and advanced operators, check out the [`LIKE` guide](/docs/salesforce/marketing-cloud-engagement/sql/sql-like.mdx).

```sql title="Broad C-Suite hunt with PATINDEX"
PATINDEX('%C_O%', JobTitle)
```

While wildcards give `PATINDEX` an edge over [`CHARINDEX`](#charindex), it misses one feature of the latter - an optional argument for starting the search from a specific string. Either can be better depending on the use case at hand.

## SUBSTRING

`SUBSTRING` cuts a part out of the middle of a value. You pass the value, the index of the first character you want and the number of characters to take. Paired with [`CHARINDEX`](#charindex), it takes everything after a character, such as the domain of an email address, which you need for deliverability reports by mailbox provider:

```sql {3} title="Email domain of each subscriber"
SELECT
      SubscriberKey
    , SUBSTRING(EmailAddress, CHARINDEX('@', EmailAddress) + 1, LEN(EmailAddress)) AS EmailDomain
FROM _Subscribers
/* EmailAddress: 'anna@example.com', Output: 'example.com' */
```

`LEN(EmailAddress)` asks for more characters than are left after the `@`, and that is fine, as `SUBSTRING` stops at the end of the value.

For the part before the `@`, use `LEFT(EmailAddress, CHARINDEX('@', EmailAddress) - 1)`, but only on values that have the `@`, for example with `WHERE EmailAddress LIKE '%@%'`. Without it, `CHARINDEX` returns 0, `LEFT` gets -1 as the number of characters, and the query fails during the run with no reason given. `SUBSTRING` is safe here, as a missing `@` makes it start from the first character and return the whole value.

## REPLACE and TRANSLATE

`REPLACE` swaps every occurrence of one text for another, so it is the find and replace of SQL. Mobile numbers from web forms are a good use, as people type them with spaces, while your SMS sends and deduplication need one format:

```sql {3} title="Remove spaces from mobile numbers"
SELECT
      SubscriberKey
    , REPLACE(MobileNumber, ' ', '') AS CleanMobileNumber
FROM Leads
/* MobileNumber: '+48 601 234 567', Output: '+48601234567' */
```

Real numbers come with brackets and hyphens as well. You could nest one `REPLACE` in another for each character, but `TRANSLATE` swaps many characters in one go. It takes the characters to find and the same number of replacements, so turn them all into one placeholder and remove it with a single `REPLACE`:

```sql {3} title="Remove spaces, brackets and hyphens at once"
SELECT
      SubscriberKey
    , REPLACE(TRANSLATE(MobileNumber, ' ()-', '####'), '#', '') AS CleanMobileNumber
FROM Leads
/* MobileNumber: '+48 (601) 234-567', Output: '+48601234567' */
```

Pick a placeholder that never appears in the real values.

## CONCAT

`CONCAT` function allows you to join two or more strings together.

You can use it on both existing values pulled from source data extension, as well as on custom strings and digits added directly in the query. In most cases, you will mix both.

```sql {4} title="Perfect for preparing your data for personalization"
SELECT
      SubscriberKey
    , EmailAddress
    , CONCAT(FirstName, ' ', LastName) AS FullName
```

You can concatenate any number of strings by just adding them comma-separated.

:::note You Should Know

In many cases, you might see concatenation done with the plus sign notation.

```sql {4} title="Same as above, but with the plus notation"
SELECT
      SubscriberKey
    , EmailAddress
    , FirstName + ' ' + LastName AS FullName
```

It might seem cleaner, but there are two downsides to this method:
1. With the plus notation, if at least one provided value is `NULL`, the outcome becomes `NULL`. `CONCAT` function treats such values as empty strings.
2. If you want to join a string with a date type value, you need to use [`CONVERT`](/docs/salesforce/marketing-cloud-engagement/sql/sql-conversion-functions.mdx#cast--convert), but `CONCAT` will do the implicit conversion for you.

:::

## STRING_AGG

`CONCAT` joins values from one row. `STRING_AGG` joins values from many rows into one, which you need whenever an email should list them, such as the categories a customer bought from:

```sql {3} title="Categories of each subscriber in one field"
SELECT
      SubscriberKey
    , STRING_AGG(Category, ', ') WITHIN GROUP (ORDER BY Category) AS Categories
FROM (
    SELECT DISTINCT
          SubscriberKey
        , Category
    FROM Orders
) AS subscriberCategory
GROUP BY SubscriberKey

/* Output:
SubscriberKey | Categories
anna-1042     | Books, Music, Travel
ben-2077      | Books, Music
chloe-3101    | Travel
*/
```

`STRING_AGG` works like the [aggregate functions](/docs/salesforce/marketing-cloud-engagement/sql/sql-aggregate-functions.mdx), so it needs `GROUP BY`. `WITHIN GROUP` sets the order of the values, as without it, the order can change between runs. There is no `DISTINCT` inside `STRING_AGG`, so the subquery removes the repeated categories first. Without it, Ben would get Books three times.

Two limits apply. On a `VARCHAR` field, such as `Status` of `_Subscribers`, `STRING_AGG` fails with ["Argument data type nvarchar is invalid for argument 2 of string_agg function."](/docs/salesforce/marketing-cloud-engagement/sql/sql-errors.mdx#string_agg-argument-data-type), as :product[MCE] [adds an `N`](/docs/salesforce/marketing-cloud-engagement/sql/sql-style-guide.mdx#apostrophes-in-comments) to every text value in your query, the separator included. And on a Text field, the result stops at 4,000 characters, so a longer list [fails the run](/docs/salesforce/marketing-cloud-engagement/sql/sql-errors.mdx#automation-failed-due-to-system-error). Convert the field to `NVARCHAR(MAX)` first, as in `STRING_AGG(CONVERT(NVARCHAR(MAX), Status), ', ')`, and neither limit applies.

## STRING_SPLIT

Web forms often save the answers of a checkbox list as one value, such as `music,travel,books`. In SQL Server, `STRING_SPLIT` turns such a value into rows. In :product[MCE], it fails just like [`OPENJSON`](/docs/salesforce/marketing-cloud-engagement/sql/sql-json-functions.mdx#openjson), as the syntax check takes it for a [Data Extension name](/docs/salesforce/marketing-cloud-engagement/sql/sql-errors.mdx#not-a-known-data-extension-or-system-data-view):

```sql {5} title="❌ STRING_SPLIT fails the syntax check"
SELECT
      preference.SubscriberKey
    , interest.value AS Interest
FROM Preferences AS preference
    CROSS APPLY STRING_SPLIT(preference.Interests, ',') AS interest
/* Error: The STRING_SPLIT(preference.Interests, table has a multi-part specification. This is not allowed.
STRING_SPLIT(preference.Interests, is not a known data extension or system data view. You can only query existing data extensions or system data views. */
```

The workaround goes through JSON. Turn the list into a JSON array with `REPLACE`, and read its items with the [array trick from my JSON article](/docs/salesforce/marketing-cloud-engagement/sql/sql-json-functions.mdx#openjson):

```sql {3,7,16} title="✅ Split a comma-separated value into rows"
SELECT
      preference.SubscriberKey
    , TRIM(JSON_VALUE(preference.InterestsJson, CONCAT('$[', interestPosition.Position, ']'))) AS Interest
FROM (
    SELECT
          SubscriberKey
        , CONCAT('["', REPLACE(STRING_ESCAPE(Interests, 'json'), ',', '","'), '"]') AS InterestsJson
    FROM Preferences
) AS preference
    INNER JOIN (
        SELECT TOP 10
              ROW_NUMBER() OVER (ORDER BY SubscriberID) - 1 AS Position
        FROM _Subscribers
        ORDER BY Position
    ) AS interestPosition
        ON JSON_VALUE(preference.InterestsJson, CONCAT('$[', interestPosition.Position, ']')) IS NOT NULL

/* Interests: 'music, travel,books'
Output:
SubscriberKey | Interest
anna-1042     | music
anna-1042     | travel
anna-1042     | books
*/
```

`STRING_ESCAPE` adds a backslash before quotes and the other characters JSON does not allow as they are. That way, one value with a quote cannot break the array and stop the whole query. `TRIM` removes the spaces people type after commas. `TOP 10` sets the maximum number of items per value, so raise it for longer lists.

## LTRIM, RTRIM and TRIM

`LTRIM` and `RTRIM` functions allow you to quickly clean your data by deleting unneeded spaces from the beginning or the end of the provided string.

```sql title="Noone likes useless whitespace in their database"
SELECT
      LTRIM('   data from webform ')    AS CleanLeftSide    /* Output: 'data from webform ' */
    , RTRIM('   data from webform ')    AS CleanRightSide   /* Output: '   data from webform' */
    , TRIM('   data from webform ')     AS CleanBothSides   /* Output: 'data from webform' */
```

Since SQL Server 2022, `LTRIM` and `RTRIM` also take the characters to remove as a second argument, which helps with zero-padded IDs from other systems: `LTRIM('007', '0')` returns `7`. `TRIM` has its own syntax for the same job, `TRIM(LEADING '0' FROM '007')`, but :product[MCE] refuses it, as its syntax check reads that `FROM` as the start of a table list: ["N'007' is not a known data extension or system data view."](/docs/salesforce/marketing-cloud-engagement/sql/sql-errors.mdx#not-a-known-data-extension-or-system-data-view)

## NEWID

`NEWID` function creates a pseudorandom identifier in the form of a 36-character string GUID (RFC4122 compliant).

The output structure is the same as for the SSJS `Platform.Function.GUID()` or AMPScript `GUID()` functions - five alphanumerical strings joined by hyphens.

```sql {1} title="Returns GUID in the form of XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX"
SELECT NEWID() AS UniqueID
```

## LOWER, UPPER and Title Case

When working with SQL, you will frequently encounter dirty data that needs some cleaning before being leveraged for personalisation in marketing sends. One of the frequent issues is inconsistent letter cases, especially on self-filled data points like first and last names coming from lead forms.

Thankfully, SQL can clean up such data with built-in `LOWER` and `UPPER`.

```sql {3-4}
SELECT
      'DIRTY Data'          AS SampleData
    , LOWER('DIRTY Data')   AS Lowercase    /* Output: 'dirty data' */
    , UPPER('DIRTY Data')   AS Uppercase    /* Output: 'DIRTY DATA' */
```

However, there is no out-of-the-box function for Proper Case - a popular requirement, especially around names and titles. The basic solution for single-word strings is straightforward:

```sql {3}
SELECT
      FirstName /* Output: 'MATEUSZ' */
    , UPPER(LEFT(FirstName, 1)) + LOWER(RIGHT(FirstName, LEN(FirstName) - 1)) AS Propercase /* Output: 'Mateusz' */
```

However, it will not work with complex (like names with a hyphen in the middle) or multi-word values. The standard SQL solution - User Defined Function - doesn't work in a limited :product[MCE] SQL environment. The alternative - using [`CHARINDEX`](#charindex)/[`PATINDEX`](#patindex) to find each word - gets awful as soon as you hit three words and more.

Recommended approach? Either clean the data before ingestion to :product[MCE] or do it directly in the email with the built-in AMPScript `ProperCase` function.

## FORMAT with Strings

`FORMAT` function lets you quickly change the data into a different format. In :product[MCE], it is especially useful, as you cannot create your functions. `FORMAT` might save you massive headaches.

The `FORMAT` works only with datetime and numeric values. Why I'm writing about it here then? Because you can use [`CONVERT`](/docs/salesforce/marketing-cloud-engagement/sql/sql-conversion-functions.mdx#cast--convert) function to change some of your strings into compliant data types. Consider changing string dates into datetime or phone numbers into integers to format them easily. Check out [`FORMAT` with Dates](/docs/salesforce/marketing-cloud-engagement/sql/sql-date-functions.mdx#format-with-dates) and [`FORMAT` with Numbers](/docs/salesforce/marketing-cloud-engagement/sql/sql-numeric-functions.mdx#format-with-numbers) for more information. The outcome of formatting both number and date types with this function is a string.
