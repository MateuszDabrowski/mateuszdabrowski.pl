SQL Studio

Query Studio, rebuilt inside your own account

SQL Studio is a free, open-source replacement for Salesforce Labs' Query Studio in Marketing Cloud Engagement (MCE). Write a query, run it, check the results right below it and save it as a Query Activity once it works. It runs inside your own MCE account as a Cloud Page App your admin deploys once, and everyone signs in with their own MCE login and permissions. No query or result ever leaves your account.

Why SQL Studio​

Query Studio was the fast, easy way to write and test SQL in MCE. Today it is no longer available on AgentExchange, so you cannot add it to an account that does not have it. Where it is still installed, it works, but Salesforce's support sends you to community resources for setup and bug fixes. And it runs outside your MCE account, on a separate server.

SQL Studio does the same job from inside your own account. Everything it creates, changes or runs for you uses your own login and permissions. It sends your SQL to MCE exactly as you wrote it and runs it as a real Query Activity, so a query that works in SQL Studio works in Automation Studio, and the other way round. And as all of its code is open on GitHub, your admin or security team can check what it does before deploying it.

Query Studio was a huge timesaver for a quick query or a check on a Data View, as I wrote in my AgentExchange Solutions overview. SQL Studio keeps what made it useful and fixes the gaps my SQL articles point out, from valid SQL that Query Studio refuses to error messages that are hard to debug.

What's inside​

Four Queries, Running at Once​

Four query tabs sit above the editor, and each keeps its own query, results and messages. Every tab runs on its own Query Activity, so you can start a long query in one tab and keep working in another. The tabs also show where each query is at a glance: a spinner while it runs, a check with the row count and run time when it finishes, and an error mark when it fails. Close SQL Studio and come back later, and your tabs in that Business Unit return with their last results, as long as their temporary Data Extensions still exist.

Every Data Extension and Data View, One Search Away​

The sidebar lists the System Data Views and your Business Unit's Data Extensions, and finds any of them as you type. Autocomplete suggests keywords, functions, tables and fields. After = or inside IN (...), it even suggests the known values of fields such as status codes and bounce categories, so you do not have to look them up elsewhere. Hover over a table or function to see what it does, with links to my field references for the System Data Views, Salesforce's documentation and Microsoft's T-SQL reference.

Lint for What Marketing Cloud Engagement Refuses​

Some SQL looks fine and still fails in MCE, sometimes only once MCE saves or runs it. SQL Studio's lint flags these problems in the editor, before you run anything, and Validate and Run then check your query against MCE's own Query Activity rules. The lint catches an unpaired apostrophe in a comment, which stops MCE from saving the query, and a query that opens with a common table expression, which MCE does not support. It also flags a Text column compared to a Number column in a join, which fails as soon as one value is not a number, and more. Every finding says in plain words what is wrong and how to fix it. Most come with a one-click fix, and Fix all applies every safe fix at once.

Paged Results and a Full CSV Export​

Run creates a temporary Data Extension, runs your query into it and opens the results in a paged, sortable grid with a filter on every column. Columns that select a Date, Number, Decimal or Boolean field keep that type, so dates sort as dates and numbers as numbers. Export CSV downloads every row, across all pages. When a run fails, you see MCE's own error message, followed by SQL Studio's explanation and fix wherever it recognises the error. That includes a query that fails while it runs, which would otherwise look like a run that found no rows.

Every run also shows how many API calls it used, and About shows the total for your session. Why does it matter? Because API calls count against your licence's yearly API limit. In my tests, a simple SELECT TOP 10 cost 10 calls in all, and a 5-minute query about 13, as SQL Studio checks on a long query less often the longer it runs.

Save, Open, History and Format​

Save as turns your query into a new Query Activity, with the target Data Extension and the Overwrite, Update or Append action you pick, and checks your columns against the target's fields before it saves. Open loads any saved Query Activity into a tab, and Save then updates it, asking before it overwrites its SQL. History keeps your past runs in your browser. Your admin can also turn on server-side history, which follows you across devices, but anyone with Data Extension access in the Business Unit can read it. Format lays your query out by my SQL style guide, the one my SQL articles follow.

Free, Commercial Use Included​

SQL Studio is free for any Marketing Cloud Engagement account, your company's and your clients' included, under the European Union Public Licence 1.2 (EUPL 1.2). Read the full text on GitHub, or the plain-language summary in the README.

Change It, Keep the Credit​

You can change SQL Studio and share it, changed or not, and installing it in someone else's account, such as a client's, counts as sharing. A shared copy comes with its source code, keeps its copyright and licence notices intact, and stays under the EUPL 1.2. The SQL Studio name and the MD logo are not licensed under the EUPL, so only an unchanged copy may keep them. A changed copy gets its own name and logo, keeps my credit in its notices, and says that it is changed, and when. Filling in the settings sections is not a change.

Frequently asked questions​

Does any of my data or SQL reach you?

No. Your browser makes two kinds of request outside your MCE account, one for the code editor's files and one for a daily update check. Neither carries your query, your results or your login, and Your data below says what each one sends.

Which Marketing Cloud Engagement edition and permissions do I need?

Enterprise 2.0 or Core edition, with Data Extension and Automation Studio permissions for every user. The "Data Extension | Manage Data Extension Retention" permission is recommended, so temporary Data Extensions expire on their own. Without it, each new run deletes the previous run's temporary Data Extension, and SQL Studio deletes your own leftovers older than six hours when you open it.

Why does SQL Studio ask me to renew my session?

Your SQL Studio session lasts about 20 minutes, like MCE's own access token, and SQL Studio renews it in the background while you work and on your first action after a break. If renewing fails, for example because you signed out of MCE, a Session expired dialog asks you to renew, and your query and results stay as they were. Why not a longer session? Because it would need a refresh token. SQL Studio keeps its tokens encrypted in its sign-in log, but someone who reads the client secret in the Backend could decrypt them, and a refresh token would stay usable for 30 days, against about 20 minutes for an access token.

Why did SQL Studio turn blue after Cmd+A?

Because the shortcut went to Marketing Cloud Engagement's own page. MCE's page has the keyboard focus right after you click its top bar, for example to switch Business Units, so Cmd+A (Ctrl+A on Windows) selects everything on it, and the browser highlights SQL Studio's whole frame along with it. SQL Studio cannot clear a selection that belongs to MCE's page, and MCE keeps it even as you move between its apps. To clear it, open the Business Unit menu and click the MID number of your current Business Unit, or reload the page. To avoid it, move the pointer over SQL Studio before you press the shortcut, as SQL Studio takes the keyboard focus back as soon as the pointer is over it.

How do I update to a new release?

Replace all of SQL Studio Frontend with the new release's file, as it has no settings. In SQL Studio Backend, and in the SQL Studio Landing Page when the release changed it, replace everything from the "APP CODE - replace from here on update" line down, then publish. Your settings sit above that line and stay as they are. Updating below has the rest.

Can I deploy SQL Studio for a client under my own brand?

Yes, as a changed copy. Installing it in a client's account counts as sharing it, so the copy comes with its source code and stays under the EUPL 1.2. Give it your own name and logo, keep my credit in its copyright and licence notices, and say that it is changed, and when. An unchanged copy keeps the SQL Studio name and logo.

Does SQL Studio support [feature X]?

What SQL Studio does today is listed above. If the feature you need isn't there, write in, as feature requests inform what ships next.


Reporting a bug

Useful details to include:

  • A short description of what happened, and what you expected instead.
  • The Frontend and Backend versions (Help → About SQL Studio).
  • Your Marketing Cloud Engagement edition, and whether you are in a parent or child Business Unit.
  • Your browser and its version.
  • The query text, if it is not sensitive, and the exact error message.
  • A screenshot, if relevant - with anything private cropped out.

Deployment guide​

SQL Studio is one Cloud Page, two Code Resources and an Installed Package, built on the pattern from my Solve with Cloud Page Apps article. The release files are ready to paste, so there is no external hosting and no build step. This section gives you the order and what to fill in. For the Data Extension fields, the troubleshooting table and every other detail, follow the full guide in the repository.

Full deployment guide on GitHub »

What you need​

  • Marketing Cloud Engagement, Enterprise 2.0 or Core edition.
  • An admin who can create Installed Packages, Code Resources and Cloud Pages.
  • Data Extension and Automation Studio permissions for every SQL Studio user. The "Data Extension | Manage Data Extension Retention" permission is recommended, so temporary Data Extensions expire on their own. Without it, each new run deletes the previous run's temporary Data Extension, and SQL Studio deletes a user's own leftovers older than six hours when they open it.
  • A modern desktop browser that can reach cdn.jsdelivr.net, where the code editor loads from. If a network policy blocks it, SQL Studio falls back to a plain text box after 15 seconds, and Run and Save still work.

Publish nothing until step 4. A piece published early, with empty settings, can keep answering with them for a few minutes after you publish the finished version, and sign-in fails until it catches up.

  1. Get the code. Download the three release files, and open them in a code editor such as the free VS Code, not in Word or TextEdit, which can turn the code's straight quotes into curly ones:

    Each link downloads the file from the latest release on GitHub. You can also download everything as one ZIP, sqlstudio-main.zip, and use the same three files from its src folder. Next to the Frontend's .min.js it also has sql-studio-frontend.js, the same code with its comments, for reading. Paste the .min.js, because MCE serves it in about 2 seconds, against 18 for the commented file on my account.

  2. Create the three pieces in a folder in Web Studio → CloudPages, without publishing them. Save each one and open it, then copy its URL from the top of the editor. If your account has private domains, CloudPages asks for URL settings as you create each piece: pick your domain, give each piece its own Site Key, such as sql-studio, sql-studio-backend and sql-studio-frontend, never a blank one, and turn HTTPS on.

The subdomain is the 28 characters that start with mc, not the Client ID. Select it by dragging, as a double-click stops at its hyphen.

  4. Paste the code, then publish. Paste each file, with its settings filled in, into its piece: select the whole file in your code editor with Ctrl+A (Cmd+A on a Mac), copy it, and paste it over everything in the piece's code in Web Studio.

On this first open, it creates its sign-in log and error log and sets their retention, and the Status tab says so once: "First run: SQL Studio created its Data Extensions in the SQL Studio folder." Only if MCE does not let it set the retention does a second notice ask you to set it by hand: 1 day for SQL Studio Auth Log and 180 days for SQL Studio Error Log. Updating​

An update replaces code and keeps your settings, in the same order as the first deployment:

  1. Replace all of SQL Studio Frontend with the new sql-studio-frontend.min.js, and publish. Up to 1.0 the Frontend was sql-studio-frontend.js: the .min.js is the same code without its comments, and opens much faster.
  2. In SQL Studio Backend, and in SQL Studio when the release changed it, replace everything from the "APP CODE - replace from here on update" line down, and publish. Your settings sit above that line and stay as they are.

A release that adds or renames a setting says so in the changelog, and until you copy its new settings section across, SQL Studio shows a message that yours is from an older release. You also do not have to watch the repository: once a day, SQL Studio checks for a new release and shows an Update badge in the toolbar, with the key changes and a link to the update guide.

Your data​

SQL Studio has no account of its own and no server of mine. Everything it creates, changes or runs for you in Marketing Cloud Engagement uses your own login, in your own account. It reads the status and results of its own runs, and the names and fields of the parent Business Unit's shared Data Extensions, through WSProxy inside MCE. The two requests your browser makes outside MCE carry no query and no result.

Where it lives​

Your queries and their results stay in MCE, in objects SQL Studio creates in your account:

  • A sign-in log, holding a hash of your session id, your access token encrypted and valid for about 20 minutes, and your MCE user id, name and email, with a 1-day retention.
  • An error log, holding backend error messages cut to 2,000 characters, never with a token, a session id or the client secret, with a 180-day retention.
  • A temporary Data Extension per run, with a 1-day retention. A new run in the same tab deletes the previous one, and once a day SQL Studio deletes your own leftovers older than six hours when you open it.
  • An optional history Data Extension, only if your admin turns it on, holding every user's own SQL text with its row count and run time, with a 90-day retention.
  • Up to four Query Activities per user, each keeping the SQL of the last query it ran. SQL Studio never deletes them.

Any user with Data Extension access in the Business Unit can read these Data Extensions while they exist, your results included. The sign-in log gives them nothing to use: the session id is stored as a hash, and the token is encrypted with a key derived from the client secret. Its rows still last one day, and SQL Studio requests no refresh tokens, so even someone who reads the client secret in the Backend finds only tokens that expire within 20 minutes. In your browser, SQL Studio keeps your tabs' query text, your local history, the Business Unit's Data Extension list and your settings, in local storage for your Cloud Page's address.

What leaves your account​

Two kinds of request, both from your browser. The Backend, which runs on MCE's servers, calls only MCE's own APIs.

  • The code editor, Monaco, loads from the jsDelivr CDN, pinned to version 0.52.2. Its loader file carries a Subresource Integrity hash, so your browser refuses it if it differs from the file SQL Studio expects, and the loader then fetches the rest of the editor from the same pinned path.
  • An update check, once a day per browser, reads a small release file from SQL Studio's GitHub repository, sending no cookies and no page address.

Neither request carries a query, a result or your login. jsDelivr and GitHub see what any server sees on a request: your IP address and your browser. For the editor's files, that usually includes your Cloud Page's domain as well. There is no analytics, no telemetry and no crash reporting. The links in the Help menu, the About dialog and hover documentation, to my articles, Microsoft Learn and Salesforce Help, open only when you click them.
