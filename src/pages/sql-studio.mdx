{/* Downloads one release file from the public repository's main branch, under its own name. A plain
    link cannot: browsers ignore the download attribute on another domain, and GitHub serves raw files
    as text, so the file would open in the tab. GitHub allows this fetch from any site. Without
    JavaScript, the link still opens the raw file. */}
export const DownloadFile = ({ path }) => {
  const name = path.split('/').pop();
  const url = `https://raw.githubusercontent.com/MateuszDabrowski/sqlstudio/main/src/${path}`;
  const [isFailed, setIsFailed] = useState(false);
  const onClick = async (event) => {
    event.preventDefault();
    try {
      const response = await fetch(url);
      if (!response.ok) throw new Error(`HTTP ${response.status}`);
      const blob = new Blob([await response.arrayBuffer()], { type: 'application/octet-stream' });
      const objectUrl = URL.createObjectURL(blob);
      const link = document.createElement('a');
      link.href = objectUrl;
      link.download = name;
      document.body.appendChild(link);
      link.click();
      link.remove();
      setTimeout(() => URL.revokeObjectURL(objectUrl), 10000);
      setIsFailed(false);
    } catch (error) {
      setIsFailed(true);
    }
  };
  return (
    <>
      <a href={url} onClick={onClick}><code>{name}</code></a>
      {isFailed && <><br/><small>The download failed. Use the ZIP below.</small></>}
    </>
  );
};

The "Data Extension | Manage Data Extension Retention" permission is recommended, so temporary Data Extensions expire on their own. Without it, each new run deletes the previous run's temporary Data Extension, and SQL Studio deletes your own leftovers older than six hours when you open it.

</details>

<details className={styles.faqDetails}>
  <summary>Who can see my snippets?</summary>

  Everyone who uses SQL Studio in your Business Unit, as sharing them is the point. In SQL Studio, only you can rename or delete your own. However, the snippets live in a Data Extension in the Business Unit that holds SQL Studio Backend, so anyone with Data Extension access there can read, change or delete them in Contact Builder. **Keep values you would not share out of a snippet's SQL.** If your team should not have snippets at all, your admin can turn them off with one line in the Backend's settings.

</details>

<details className={styles.faqDetails}>
  <summary>Why does SQL Studio ask me to renew my session?</summary>

  Your SQL Studio session lasts about 20 minutes, like MCE's own access token, and SQL Studio renews it in the background while you work and on your first action after a break. If renewing fails, for example because you signed out of MCE, a Session expired dialog asks you to renew, and your query and results stay as they were. Why not a longer session? Because it would need a refresh token. SQL Studio keeps its tokens encrypted in its sign-in log, but someone who reads the client secret in the Backend could decrypt them, and a refresh token would stay usable for 30 days, against about 20 minutes for an access token.

</details>

<details className={styles.faqDetails}>
  <summary>Why did SQL Studio turn blue after Cmd+A?</summary>

  Because the shortcut went to Marketing Cloud Engagement's own page. MCE's page has the keyboard focus right after you click its top bar, for example to switch Business Units, so Cmd+A (Ctrl+A on Windows) selects everything on it, and the browser highlights SQL Studio's whole frame along with it. SQL Studio cannot clear a selection that belongs to MCE's page, and MCE keeps it even as you move between its apps. To clear it, open the Business Unit menu and click the MID number of your current Business Unit, or reload the page. To avoid it, **move the pointer over SQL Studio before you press the shortcut**, as SQL Studio takes the keyboard focus back as soon as the pointer is over it.

</details>

<details className={styles.faqDetails}>
  <summary>How do I update to a new release?</summary>

  Replace all of SQL Studio Frontend with the new release's file, as it has no settings. In SQL Studio Backend, and in the SQL Studio Landing Page when the release changed it, replace everything from the "APP CODE - replace from here on update" line down, then publish. Your settings sit above that line and stay as they are. [Updating](#updating) below has the rest.

</details>

<details className={styles.faqDetails}>
  <summary>Can I deploy SQL Studio for a client under my own brand?</summary>

  Yes, as a changed copy. Installing it in a client's account counts as sharing it, so the copy comes with its source code and stays under the EUPL 1.2. Give it your own name and logo, keep my credit in its copyright and licence notices, and say that it is changed, and when. An unchanged copy keeps the SQL Studio name and logo.

</details>

<details className={styles.faqDetails}>
  <summary>Does SQL Studio support [feature X]?</summary>

  What SQL Studio does today is listed above. If the feature you need isn't there, write in, as feature requests inform what ships next.

</details>

## Deployment guide {#deployment-guide}

<p>SQL Studio is one Cloud Page, two Code Resources and an Installed Package, built on the pattern from my <Link to="/docs/salesforce/marketing-cloud-engagement/ssjs/snippets/sfmc-cloud-page-apps/">Solve with Cloud Page Apps</Link> article. The release files are ready to paste, so there is no external hosting and no build step. This section gives you the order and what to fill in. For the Data Extension fields, the troubleshooting table and every other detail, follow the full guide in the repository.</p>

<p><a href="https://github.com/MateuszDabrowski/sqlstudio/blob/main/docs/DEPLOYMENT.md">Full deployment guide on GitHub »</a></p>

    <div style={{marginTop: '2rem'}}>

### What you need

    </div>

<ul>
  <li>Marketing Cloud Engagement, Enterprise 2.0 or Core edition.</li>
  <li>An admin who can create Installed Packages, Code Resources and Cloud Pages.</li>
  <li>Data Extension and Automation Studio permissions for every SQL Studio user. The "Data Extension | Manage Data Extension Retention" permission is recommended, so temporary Data Extensions expire on their own. Without it, each new run deletes the previous run's temporary Data Extension, and SQL Studio deletes a user's own leftovers older than six hours when they open it.</li>
  <li>A modern desktop browser that can reach <code>cdn.jsdelivr.net</code>, where the code editor loads from. If a network policy blocks it, SQL Studio falls back to a plain text box after 15 seconds, and Run and Save still work.</li>
</ul>

## <span style={{color: 'var(--ifm-color-white)'}}>Your data</span> {#your-data}

<p style={{color: 'var(--ifm-color-white)', fontSize: '1.1rem', maxWidth: '760px'}}>SQL Studio has no account of its own and no server of mine. Everything it creates, changes or runs for you in Marketing Cloud Engagement uses your own login, in your own account. Shared snippets are the one exception, as the Backend keeps them in its own Data Extension and checks every change against your sign-in. It reads the status and results of its own runs, and the names and fields of the parent Business Unit's shared Data Extensions, through WSProxy inside MCE. The two requests your browser makes outside MCE carry no query and no result.</p>

    <div className="row" style={{marginTop: '2rem'}}>
      <div className="col col--6" style={{padding: '1rem 2rem'}}>

        <div style={{marginBottom: '1rem'}}>

### <span style={{color: 'var(--ifm-color-white)', fontSize: '1.5rem'}}>Where it lives</span>

        </div>

        <p style={{color: 'var(--ifm-color-white)', fontSize: '1.05rem'}}>Your queries and their results stay in MCE, in objects SQL Studio creates in your account:</p>
        <ul style={{color: 'var(--ifm-color-white)', fontSize: '1.05rem'}}>
          <li><strong>A sign-in log</strong>, holding a hash of your session id, your access token encrypted and valid for about 20 minutes, and your MCE user id, name and email, with a 1-day retention.</li>
          <li><strong>An error log</strong>, holding backend error messages cut to 2,000 characters, never with a token, a session id or the client secret, with a 180-day retention.</li>
          <li><strong>A temporary Data Extension per run</strong>, with a 1-day retention. A new run in the same tab deletes the previous one, and once a day SQL Studio deletes your own leftovers older than six hours when you open it.</li>
          <li><strong>An optional history Data Extension</strong>, only if your admin turns it on, holding every user's own SQL text with its row count and run time, with a 90-day retention.</li>
          <li><strong>Up to four Query Activities per user</strong>, each keeping the SQL of the last query it ran. SQL Studio never deletes them.</li>
          <li><strong>A shared snippets Data Extension</strong>, unless your admin turns snippets off, created on the first save. It holds each snippet's name and SQL with its author's MCE user id and email, with no retention.</li>
          <li><strong>The Data Extensions you save results into</strong>, in the folder and with the retention you pick. SQL Studio never deletes them.</li>
        </ul>
        <p style={{color: 'var(--ifm-color-white)', fontSize: '0.95rem', opacity: 0.85}}>Any user with Data Extension access in the Business Unit can read these Data Extensions while they exist, your results included. The sign-in log gives them nothing to use: the session id is stored as a hash, and the token is encrypted with a key derived from the client secret. Its rows still last one day, and SQL Studio requests no refresh tokens, so even someone who reads the client secret in the Backend finds only tokens that expire within 20 minutes. In your browser, SQL Studio keeps your tabs' query text, your local history, the Business Unit's Data Extension list and your settings, in local storage for your Cloud Page's address.</p>
      </div>
      <div className="col col--6" style={{padding: '1rem 2rem'}}>

        <div style={{marginBottom: '1rem'}}>

### <span style={{color: 'var(--ifm-color-white)', fontSize: '1.5rem'}}>What leaves your account</span>

        </div>

        <p style={{color: 'var(--ifm-color-white)', fontSize: '1.05rem'}}>Two kinds of request, both from your browser. The Backend, which runs on MCE's servers, calls only MCE's own APIs.</p>
        <ul style={{color: 'var(--ifm-color-white)', fontSize: '1.05rem'}}>
          <li><strong>The code editor</strong>, Monaco, loads from the jsDelivr CDN, pinned to version 0.52.2. Its loader file carries a Subresource Integrity hash, so your browser refuses it if it differs from the file SQL Studio expects, and the loader then fetches the rest of the editor from the same pinned path.</li>
          <li><strong>An update check</strong>, once a day per browser, reads a small release file from SQL Studio's GitHub repository, sending no cookies and no page address.</li>
        </ul>
        {/* CHECK: the Cloud Page's domain on the editor requests is the browser's default
            referrer policy. Confirm in DevTools (Referer header on loader.js). */}
        <p style={{color: 'var(--ifm-color-white)', fontSize: '1.05rem'}}>Neither request carries a query, a result or your login. jsDelivr and GitHub see what any server sees on a request: your IP address and your browser. For the editor's files, that usually includes your Cloud Page's domain as well. There is no analytics, no telemetry and no crash reporting. The links in the Help menu, the About dialog and hover documentation, to my articles, Microsoft Learn and Salesforce Help, open only when you click them.</p>
