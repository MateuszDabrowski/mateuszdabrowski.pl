### <span style={{color: 'var(--ifm-color-primary)', fontSize: '2rem'}}>Lint for What Marketing Cloud Engagement Refuses</span> {#lint}

      </div>
      <p style={{fontSize: '1.1rem'}}>Some SQL looks fine and still fails in MCE, sometimes only once MCE saves or runs it. SQL Studio's lint flags these problems in the editor, before you run anything, and Validate and Run then check your query against MCE's own Query Activity rules. The lint catches an unpaired apostrophe in a comment, which stops MCE from saving the query, and a query that opens with a common table expression, which MCE does not support. It knows the valid T-SQL that MCE's own query check refuses, such as tables separated by commas, which MCE calls an old style JOIN, and a window function in WHERE. It flags functions newer than the SQL Server 2022 that MCE runs, such as REGEXP_LIKE, and a Text column compared to a Number column in a join, which fails as soon as one value is not a number, and more. And it reports nothing for valid SQL that MCE runs, such as GROUPING SETS, join hints and TABLESAMPLE. These rules come from 400 tests on a real MCE account, which also showed that MCE's save treats a <code>--</code> line comment as never closed, so everything below it becomes part of the comment. The lint flags every line comment and writes it as a block comment in one click. Every finding says in plain words what is wrong and how to fix it. Most come with a one-click fix, and **Fix all** applies every safe fix at once.</p>

</details>

<details className={styles.faqDetails}>
  <summary>Who can see my snippets?</summary>

  Everyone who uses SQL Studio in your Business Unit, as sharing them is the point. In SQL Studio, only you can rename or delete your own. However, the snippets live in a Data Extension in the Business Unit that holds SQL Studio Backend, so anyone with Data Extension access there can read, change or delete them in Contact Builder. **Keep values you would not share out of a snippet's SQL.** If your team should not have snippets at all, your admin can turn them off with one line in the Backend's settings.

</details>

<details className={styles.faqDetails}>
  <summary>Why does SQL Studio ask me to renew my session?</summary>

  Your SQL Studio session lasts about 20 minutes, like MCE's own access token, and SQL Studio renews it in the background while you work and on your first action after a break. If renewing fails, for example because you signed out of MCE, a Session expired dialog asks you to renew, and your query and results stay as they were. Why not a longer session? Because it would need a refresh token. SQL Studio keeps its tokens encrypted in its sign-in log, but someone who reads the client secret in the Backend could decrypt them, and a refresh token would stay usable for 30 days, against about 20 minutes for an access token.

</details>

<details className={styles.faqDetails}>
  <summary>Why did SQL Studio turn blue after Cmd+A?</summary>

  Because the shortcut went to Marketing Cloud Engagement's own page. MCE's page has the keyboard focus right after you click its top bar, for example to switch Business Units, so Cmd+A (Ctrl+A on Windows) selects everything on it, and the browser highlights SQL Studio's whole frame along with it. SQL Studio cannot clear a selection that belongs to MCE's page, and MCE keeps it even as you move between its apps. To clear it, open the Business Unit menu and click the MID number of your current Business Unit, or reload the page. To avoid it, **move the pointer over SQL Studio before you press the shortcut**, as SQL Studio takes the keyboard focus back as soon as the pointer is over it.

</details>

## <span style={{color: 'var(--ifm-color-white)'}}>Your data</span> {#your-data}

<p style={{color: 'var(--ifm-color-white)', fontSize: '1.1rem', maxWidth: '760px'}}>SQL Studio has no account of its own and no server of mine. Everything it creates, changes or runs for you in Marketing Cloud Engagement uses your own login, in your own account. Shared snippets are the one exception, as the Backend keeps them in its own Data Extension and checks every change against your sign-in. It reads the status and results of its own runs, and the names and fields of the parent Business Unit's shared Data Extensions, through WSProxy inside MCE. The requests your browser makes outside MCE carry no query and no result, and the one way a query leaves your account is Document, which hands its names and expressions to Diagramforce inside your browser.</p>

    <div className="row" style={{marginTop: '2rem'}}>
      <div className="col col--6" style={{padding: '1rem 2rem'}}>

        <div style={{marginBottom: '1rem'}}>

### <span style={{color: 'var(--ifm-color-white)', fontSize: '1.5rem'}}>Where it lives</span>

        </div>

        <p style={{color: 'var(--ifm-color-white)', fontSize: '1.05rem'}}>Your queries and their results stay in MCE, in objects SQL Studio creates in your account:</p>
        <ul style={{color: 'var(--ifm-color-white)', fontSize: '1.05rem'}}>
          <li><strong>A sign-in log</strong>, holding a hash of your session id, your access token encrypted and valid for about 20 minutes, and your MCE user id, name and email, with a 1-day retention.</li>
          <li><strong>An error log</strong>, holding backend error messages cut to 2,000 characters, never with a token, a session id or the client secret, with a 180-day retention.</li>
          <li><strong>A temporary Data Extension per run</strong>, with a 1-day retention. A new run in the same tab deletes the previous one, and once a day SQL Studio deletes your own leftovers older than six hours when you open it.</li>
          <li><strong>An optional history Data Extension</strong>, only if your admin turns it on, holding every user's own SQL text with its row count and run time, with a 90-day retention.</li>
          <li><strong>Up to four Query Activities per user</strong>, each keeping the SQL of the last query it ran. SQL Studio never deletes them.</li>
          <li><strong>The Action Log of those Query Activities</strong>, which MCE keeps for every run. When a run fails, the entry can quote the value of the row that failed, such as an email address the query tried to turn into a number. Anyone who can open the activity in Automation Studio can read it, and deleting the activity does not delete its log. TRY_CAST and TRY_CONVERT return NULL for such a value instead, and leave nothing in the log.</li>
          <li><strong>A shared snippets Data Extension</strong>, unless your admin turns snippets off, created on the first save. It holds each snippet's name and SQL with its author's MCE user id and email, with no retention.</li>
          <li><strong>The Data Extensions you save results into</strong>, in the folder and with the retention you pick. SQL Studio never deletes them, and it replaces the rows of one you already have only with Overwrite, after asking.</li>
        </ul>
        <p style={{color: 'var(--ifm-color-white)', fontSize: '0.95rem', opacity: 0.85}}>Any user with Data Extension access in the Business Unit can read these Data Extensions while they exist, your results included.
